# M9 — Go-live

Goal: nightly backups, keep-alive, transcription and storage checks running from the private ops repo, with a proven restore; Google sign-in and email codes; previews isolated from real data; the database password reset. **Must be done before any real data goes into production** ([roadmap gate](../docs/roadmap.md#gate-before-real-data)). Nothing earlier depends on it.

Until M9 is done: if a Supabase project pauses after a week without use, resume it from the Supabase dashboard; feedback voice notes can be played in the app without transcripts.

---

### M9-01 Nightly job: backup + keep-alive + storage check
**Lane** Platform · **Depends** M0-11, H6, H7 · **Spec** [05-ops § Nightly job](../docs/architecture/05-ops.md#nightly-job)

- Job scripts in `jobs/` (public repo); the `nightly.yml` workflow lives in the **private ops repo**, checks out the public repo, and runs backup, keep-alive and storage-check steps (transcription comes in M9-02). No data may appear in logs (D29).
- **Restore drill**: restore the first backup into a local Postgres and record the result in 05-ops.

**Accept**
- [ ] An encrypted artifact exists after a manual run; it decrypts and restores into a local Postgres
- [ ] Simulated > 70% storage opens a GitHub issue

### M9-02 Nightly transcription + audio retention
**Lane** Platform · **Depends** M1-02, M9-01 · **Spec** [05-ops § Nightly job](../docs/architecture/05-ops.md#nightly-job)

- `jobs/transcribe.py` (faster-whisper `small`, int8, CPU); retention deletion step.

**Accept**
- [ ] A fixture recording (synthetic speech, committed) transcribes in CI with a non-empty transcript
- [ ] Audio older than the retention setting is deleted and `audio_deleted_at` is set

### M9-03 Ops readiness check
**Lane** QA · **Depends** M9-01, M9-02, M9-04, M9-05

- Run the nightly workflow manually; confirm that every step succeeds, the logs contain no names, notes or transcripts (ids and counts only), and the restore drill result is recorded in 05-ops.

**Accept**
- [ ] Checklist attached to the PR; the Integrator confirms the go-live gate in the roadmap

### M9-04 Google sign-in and email codes
**Lane** Platform · **Depends** M0-06, H3, H4 · **Spec** [03 § Sign-in](../docs/architecture/03-auth-and-access.md#sign-in-d3), D3

- Add "Continue with Google" and "Email me a code" to `/login` alongside password; `/auth/callback`; the same invite allowlist.

**Accept**
- [ ] An invited user signs in with Google and with an email code; an uninvited one gets the "not invited" message
- [ ] Password sign-in still works

### M9-05 Go-live hardening
**Lane** Platform · **Depends** M9-01 · **Spec** D30, [05-ops § Human setup](../docs/architecture/05-ops.md#human-setup-one-time)

- Decide preview isolation for real data. Recommended: previews lose database access (the env vars are removed from Preview), or move to a second free Supabase project. Record the choice in D30.
- Wipe demo data from the project (a script that deletes only rows created by `seed-demo`, run after a fresh backup).
- Human: reset the database password (H9) and update the connection strings in Vercel and the ops repo.

**Accept**
- [ ] A preview deployment can't read production data
- [ ] No demo rows remain; the bootstrap admin and lookups remain
