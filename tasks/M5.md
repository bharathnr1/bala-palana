# M5 — Admissions

Goal: enquiry → stages → convert to student, with history kept on the same record (D5).

---

### M5-01 Admissions domain
**Lane** Feature A · **Depends** M0-04 · **Spec** [02-schema § Admissions](../docs/architecture/02-schema.md#admissions)

- Create an enquiry (child `applicant` + guardian + admission); add event; change status (writes a `status_change` event); set next action and follow-up; `v_admissions_funnel`; add admission follow-ups to `v_open_follow_ups`; add events to `v_child_timeline`.

**Accept**
- [ ] A status change always logs an event (DB test)
- [ ] Admission follow-ups appear on Home for the assigned user

### M5-02 Admissions board
**Lane** Feature A · **Depends** M5-01 · **Spec** [04-ui-spec § Admissions](../docs/architecture/04-ui-spec.md#admissions-admissions)

- Mobile status tabs with counts / desktop kanban; card detail with events timeline, add event, change status.

**Accept**
- [ ] Terminal statuses (`meta.terminal`) are collapsed by default

### M5-03 Convert to student
**Lane** Feature B · **Depends** M5-01

- A dialog: consent confirmation (sets `consent_given_at`), joined date, grade, outside school → stage `student` + first enrolment; the Admission tab on the profile shows the history.

**Accept**
- [ ] Converting without consent is rejected server-side
- [ ] After conversion, admission events still show in the Journey

### M5-04 E2E
**Lane** QA · **Depends** M5-02, M5-03

- A coordinator creates an enquiry → interview event → selected → converts → the child appears in the Children list.

**Accept**
- [ ] Green in CI
