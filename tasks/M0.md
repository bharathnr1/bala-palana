# M0 — Skeleton

Goal: an installable app, live, with sign-in, the full schema, children CRUD, settings and CSV import.

---

### M0-01 Scaffold the app
**Lane** Platform · **Depends** — · **Spec** [01-conventions](../docs/architecture/01-conventions.md)

- Next.js (App Router, TS strict), pnpm, Tailwind, shadcn/ui init, ESLint + Prettier, Vitest, Playwright.
- Folder layout exactly as in 01-conventions; empty `strings.ts`; `src/lib/env.ts` (Zod, incl. the `AUTH_MODE` production guard).
- `src/lib/dates.ts`, `academic-year.ts`, `money.ts` with unit tests.
- Scripts: `dev`, `build`, `vercel-build`, `lint`, `typecheck`, `test`, `test:db`, `e2e`, `check`, `db:generate`, `db:migrate`, `seed:demo`.
- `.env.example`, `.nvmrc`; README "Development" section.

**Accept**
- [ ] `pnpm check` passes on a fresh clone
- [ ] `academicYearOf('2026-05-31', 6) === '2025-26'` and `academicYearOf('2026-06-01', 6) === '2026-27'`
- [ ] `formatINR(123456)` → `₹1,234.56`

### M0-03 Database foundation
**Lane** Platform · **Depends** M0-01 · **Spec** [02-schema](../docs/architecture/02-schema.md)

- Drizzle config (`casing: 'snake_case'`), `src/server/db/client.ts`, `mutate(user, fn)`.
- Migration: extensions, all enums, `lookup`, `setting`, `app_user`, `audit_log`, the `audit_row()` trigger function, the `updated_at` trigger function.
- DB test harness (per-test transaction rollback).

**Accept**
- [ ] A write via `mutate` produces an `audit_log` row with `actor_id`
- [ ] `updated_at` changes on update

### M0-04 Full domain schema (D24)
**Lane** Platform · **Depends** M0-03 · **Spec** [02-schema § Tables](../docs/architecture/02-schema.md#tables)

- Every remaining table, constraint and index from 02-schema; audit + `updated_at` triggers on all domain tables.
- RLS enabled on every table with no policies.

**Accept**
- [ ] Schema matches 02-schema (a reviewer checks table by table)
- [ ] DB tests: cycle overlap rejected; assessment check constraints; `entry.note` length check
- [ ] As the `anon` role, `select` from any table returns 0 rows or is denied

### M0-05 Seeds and demo data
**Lane** Platform · **Depends** M0-04 · **Spec** [02-schema § Seeds](../docs/architecture/02-schema.md#seeds), [06-testing § Fixtures](../docs/architecture/06-testing.md#fixtures)

- Idempotent seed migration: lookups, settings, bootstrap admin (from env at migrate time; skipped if unset).
- `scripts/seed-demo.ts` (deterministic). Fill only the tables that exist and grow it as milestones land; the full fixture set is required by M8.

**Accept**
- [ ] Running the seed twice changes nothing
- [ ] `pnpm seed:demo` on an empty DB creates one user per role and ~120 children with guardians and enrolments

### M0-06 Authentication and permissions
**Lane** Platform · **Depends** M0-04 · **Spec** [03-auth-and-access](../docs/architecture/03-auth-and-access.md)

- `@supabase/ssr` clients, `middleware.ts`, `/login` (**email + password**; Google and email codes come in M9-04), invite allowlist, `requireUser()`, sign-out, *Account → Change password*.
- `permissions.ts` (`can`, `assertCan`) + the `action()` wrapper.
- Test auth mode.

**Accept**
- [ ] An uninvited email is signed out with the "not invited" message
- [ ] A deactivated user is signed out on their next request
- [ ] Unit test: the matrix matches 03 for every role × action
- [ ] App refuses to boot with `AUTH_MODE=test` whenever `VERCEL_ENV` is set

### M0-07 App shell and PWA
**Lane** Feature A · **Depends** M0-06 · **Spec** [04-ui-spec § Navigation, PWA](../docs/architecture/04-ui-spec.md#navigation)

- Signed-in layout: bottom bar (mobile) / sidebar (desktop), role-filtered items, placeholder pages for every route.

### M0-08 Children list, profile shell, add/edit
**Lane** Feature A · **Depends** M0-07 · **Spec** [04-ui-spec § Children, Child profile](../docs/architecture/04-ui-spec.md#children-children)

- `server/children` queries and actions; `/children` with search (trigram) and filters; `/children/new` and edit (basic fields + primary guardian + current enrolment); profile header and empty tabs; "recently viewed" tracking (per user, in `setting` or local storage).

**Accept**
- [ ] Search "ana" finds "Ananya" among 120 demo children in < 300 ms (DB test timing)
- [ ] A teacher can view but not edit; coordinator and admin can edit

### M0-09 Settings: users, lists, preferences
**Lane** Feature B · **Depends** M0-07 · **Spec** [04-ui-spec § Settings](../docs/architecture/04-ui-spec.md#settings-settings-admin)

- Users: add (creates the `app_user` row + the Supabase auth account with a temporary password via the admin API), reset password, change role, deactivate (also bans the auth account; can't deactivate yourself or the last admin).
- Lists: one tab per lookup kind; add, rename, reorder, deactivate (no hard delete).
- Preferences: the four settings with validation.

**Accept**
- [ ] A deactivated lookup disappears from pickers but still shows on old records
- [ ] Removing the last admin is rejected

### M0-10 CSV import
**Lane** Feature B · **Depends** M0-08 · **Spec** [design §4](../docs/design-doc.md#4-key-screens)

- A downloadable template (child, guardian, grade, outside school); upload → validate → preview table with row errors → import in one transaction; summary.

**Accept**
- [ ] A file with 1 bad row of 120 shows the error and imports nothing until it's fixed or that row is excluded
- [ ] Re-importing the same file creates no duplicates (match on name + dob)

### M0-11 Deploy pipeline
**Lane** Platform · **Depends** M0-04, H2, H5 · **Spec** [05-ops § Deploys](../docs/architecture/05-ops.md#deploys), D30

- `vercel.json` with `buildCommand: pnpm vercel-build`; migrate only when `VERCEL_ENV=production`; `next build` always.
- Production runs the seed migration, so lookups, settings and the bootstrap admin's `app_user` row exist.

**Accept**
- [ ] A merged PR with a migration deploys and migrates the database; a preview build of an unmerged PR does not
- [ ] The bootstrap admin can sign in at https://bala-palana.vercel.app
